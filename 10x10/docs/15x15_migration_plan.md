# 15×15 전환 준비 목록

작성: 2026-10-13 밤 · 사용자 결정: 15×15로 전환 (11×11은 축제용으로 고정)

## 0. 원칙

- **11×11은 건드리지 않는다.** 축제 모델(best = ep960, 대등국면 3,454)과 웹 대국판(`hlt/web/server.py --lan`)은 그대로 둔다.
- **15×15는 별도 폴더 `final/15x15/`에서 진행한다.** 11×11 코드(`final/10x10/`)를 복사해서 시작하고, 원본은 수정하지 않는다.
- 모델·버퍼·보고서 파일 이름은 `_SUFFIX`가 판 크기에서 자동으로 만들어진다 (`_15x15`). 같은 폴더에 섞여도 겹치지 않지만, 폴더를 나누는 게 안전하다.
- 3×3 / 5×5 / clean_3x3은 이번 작업에서도 절대 건드리지 않는다.
- 학습 데이터 순수성: Rapfi 100노드 지도학습은 **에포크 0의 출발점에만** 쓴다. 이후에는 자가대국 데이터만 쓴다.

## 1. 판 크기 상수 (2곳 — 반드시 둘 다)

| `fast_board.py` | 9 | `BOARD_SIZE = 11` | `15` |

- `alphago_lee.py`의 상수는 신경망 기본 크기에 쓰인다 (`AlphaZeroTicTacToeV3(board_size=...)`). 하나만 바꾸면 신경망과 판 크기가 어긋난다.
- 확인 필요: `alphago_lee.py` 22번 줄 주석처럼 판 크기를 전제로 한 계산(창 개수 등)이 코드에 있는지.

## 5. 신경망과 지도학습 (에포크 0)

1. **신경망:** `AlphaZeroTicTacToeV3(board_size=15)` — 9.01M 파라미터 (11×11은 8.60M). 측정: 국면당 GPU 1.97ms (11×11의 약 1.5배).
2. **선택 사항 — 11×11 몸통 이어받기:** 합성곱 몸통은 판 크기와 무관하므로 11×11 best(ep960)의 몸통을 복사하고 정책·가치·생존 머리만 새로 만들 수 있다. 지도학습 시간을 줄이고 실력을 이어받는다. (결정 필요)
3. **Rapfi 100노드 정답 데이터:**
   - 국면 만들기: Rapfi끼리(100노드, 중앙 근처 무작위 2수로 시작) 대국. 측정: 한 수 약 16ms → 30만 국면에 한 프로세스 약 80분, 4개 병렬 약 20분.
   - 정책 정답: 각 국면에서 Rapfi 100노드가 고른 수 (원-핫) — 또는 여러 노드에서 고른 수를 섞어 분포로 (결정 필요)
   - 가치 정답: Rapfi끼리 끝까지 둔 결과(z)로 할지, Rapfi 평가값으로 할지 (결정 필요)
   - Rapfi는 15×15 1,000노드에서 응답이 엇갈리는 오류를 냈음 → 오류 시 엔진을 다시 켜고 그 판을 버리는 처리 필수 (오늘 `rapfi_len15b.py`에서 검증).
4. **에포크 0 모델 보관 + 사다리 측정** (출발점 기록, "선생님 대비 몇 배" 비교용).

## 6. 학습 설정 (11×11의 2026-10-13 설정을 그대로)

`_restart_train.py`와 학습 코드의 현재 값을 복사:
- 게이트: 패배 −0.75, 기준 0.35, **통과 = 후보** (`GATE_CANDIDATE_MODE = True`)
- 후보 확인: 사다리(25개 시작 국면) 대등국면 ≥ best, P ≥ 60%, 졸업 문제 ≥ best
- 정기 측정 승격: P ≥ 90%
- 리그 상대 수는 정답에서 제외 (`RECORD_LEAGUE_SIDE = False`)
- 전체 탐색 1,600 (`SIM_RAMP_CEILING = 1600`), 빠른 탐색 300, PCR 0.5
- 온도 4수, q 가중치 0.2 고정, LR 피크 2e-5 (코사인 T_0=150)
- 옵티마이저 상태 저장 + 새 옵티마이저 LR 웜업 (0.1/0.3/0.6)
- 버퍼 최소 4만 국면 대기 (`NAPS_MIN_BUFFER`), 최대 196,608

확인 필요:
- **지도학습 → 자가대국 넘어갈 때의 LR:** 예전 미니맥스 지도학습 후 가중치가 떠내려간 전례가 있음. 웜업 + 낮은 피크로 시작.
- 리그 상대 수: 처음에는 과거 모델이 거의 없음 → 리그 대국 수를 줄이거나 지도학습 모델을 상대로.
- 자가대국 작업자 8개 유지 (GPU 발열).

## 8. 실행 순서

1. `final/15x15/` 만들고 11×11 코드 복사 (학습·MCTS·자가대국·측정 도구·`.pyd`)
2. 상수 2곳(1번) + 직접 박힌 값(2·3번) 수정
3. 빠른 점검: 15×15 빈 판에서 자가대국 1판, 게이트 1번, 사다리 1단계가 오류 없이 도는지
4. Rapfi 100노드 정답 데이터 생성 (약 20~80분)
5. 지도학습 → 에포크 0 모델 저장 → 사다리 측정
6. 학습 시작 (워치독·사다리 감시·문자 감시 15×15용으로)
7. 15×15 졸업 문제 만들기 (학습과 병행, CPU 위주)

## 9. 일정 추정 (오늘 측정 기준)

- 준비(1~5번): 약 1~2일
- 에포크 시간: 약 21~32분 (11×11의 1.0~1.5배: 계산 1.5배, 판 길이는 거의 같음)
- 하루 약 45~68에포크 → 축제 전 약 540~820에포크
- NAPS 기록 기준: 약 120노드 → 여명(959) 22시간, → 960(3,454) 약 156시간
  → 15×15 예상: 여명 수준 1~1.5일, 960 수준 6.5~10일

## 10. 결정이 필요한 것

1. 11×11 몸통을 이어받을지 (5번 2항)
2. 지도학습 정책 정답: Rapfi 한 수(원-핫) / 분포
3. 지도학습 가치 정답: 대국 결과 z / Rapfi 평가값
4. 15×15 사다리 단계(노드 수)의 시작 범위
5. 15×15 졸업 문제를 만드는 방법과 시점
