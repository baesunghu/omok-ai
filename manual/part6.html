6.1 이 부록을 쓰는 법

0~5부가 "이야기"라면 6부는 "사전"이야. 앞에서 읽다가 모르는 단어가 나오면 여기 용어집에서 찾아보고, 설정값 숫자가 뭘 뜻하는지 궁금하면 6.3의 표를 보면 돼. 어떤 파일이 무슨 일을 하는지 헷갈리면 6.5 저장소 지도를 보면 되고. 마지막 6.7~6.10은 "앞으로"에 관한 내용이야. 아직 못 푼 문제가 뭔지, 시험 끝나고 뭘 할지, 15x15로 넘어갈 때 무엇을 챙겨야 하는지, 그리고 이 코드를 처음부터 다시 공부한다면 어떤 순서로 읽으면 좋은지를 정리했어.

출처 원칙. 이 부록에 나오는 숫자와 코드는 전부 저장소 파일(_restart_train.py, alphazero_mcts_make_lrfix.py, alphazero_mcts_lrfix.py, selfplay_mp_unified.py, alphago_lee*.py, rapfi_ladder.py, tactical_problem_check.py, hlt/web/server.py, cpp_mcts/mcts_core_solver.cpp)과 메모리 노트, model/graduated_11x11/README.txt에서 직접 읽은 거야. 직접 확인 못 한 내용은 "(확인 못 함)"이라고 따로 표시했어. 코드는 2026-10-06에 읽은 상태라서 그 뒤에 바뀌었을 수도 있어.

6.2 용어집

형식: 한국어 (English) 다음에 한 문단 설명. 가나다순이 아니라 "앞 개념을 알아야 뒤 개념이 이해되는" 순서로 묶었어. 처음부터 순서대로 읽으면 그대로 작은 교과서가 되도록 짰어. 항목은 모두 100개 넘게 있어.

A. 오목과 게임 이론

1. 오목 / 자유룰 (Gomoku / Freestyle)
가로·세로·대각선 중 한 방향으로 같은 색 돌 다섯 개를 먼저 이으면 이기는 게임이야. "자유룰"은 금수(쌍삼 금지 같은 규칙)가 없고, 여섯 개 이상(장목)도 승리로 치는 가장 단순한 규칙이야. 이 프로젝트는 처음부터 끝까지 자유룰이고, 웹 기보 SGF에도 RU[freestyle]로 적혀 있어.
2. 11x11 보드 (11x11 board)
표준 15x15보다 작은 판이야. 코드에서는 alphago_lee.py의 BOARD_SIZE = 11, WIN_LENGTH = 5로 정해져 있고, 칸 수는 NUM_CELLS = 121이야. 폴더 이름이 10x10인 건 처음에 10x10으로 시작했다가 판 크기만 바꿨기 때문이야(역사적인 이유).
3. 흑/백, X/O (first/second player)
먼저 두는 쪽과 나중에 두는 쪽. 코드와 웹에서는 X가 선공, O가 후공이야. 웹 서버 server.py는 "사람 선공" if r["human"] == "X"처럼 사람이 X를 잡으면 선공으로 집계해.
4. 수 / 플라이 (move / ply)
한쪽이 돌 하나를 두는 것을 1 ply라고 해. "13-ply 방어"는 앞으로 13번의 착수(양쪽 합산)를 내다봐야 막을 수 있는 방어라는 뜻이야. 바둑에서 말하는 "수"와 같은 단위야.
5. 오 / 사 / 삼 (five / four / three)
한 줄 위에 내 돌이 몇 개 모여 있는지를 부르는 이름이야. 오(5)는 승리, 사(4)는 다음 수에 오가 되는 상태, 삼(3)은 두 수 뒤에 오가 될 수 있는 상태야.
6. 열린 사 / 닫힌 사 (open four / closed four)
양쪽 끝이 모두 비어 있는 사가 열린 사야. 상대가 한쪽을 막아도 다른 쪽으로 오를 만들 수 있으니 열린 사가 생기면 사실상 이긴 거야. 한쪽이 막혀 있으면 닫힌 사인데, 이건 상대가 남은 한 칸만 막으면 끝나. 대신 상대가 반드시 응수해야 하기 때문에 "선수"를 잡는 도구로 쓰여.
7. 열린 삼 / 닫힌 삼 (open three / closed three)
양쪽이 열린 삼은 막지 않으면 다음 수에 열린 사가 되기 때문에 상대가 응수해야 해. 닫힌 삼은 위협이 약해. 학습 로그에 나오는 track_open3_*.log는 열린 삼 대응을 추적하던 모니터의 출력이야.
8. 띈 삼 / 띈 사 (split three / broken four)
XX.X처럼 중간에 빈칸이 끼어 있는 형태야. 사람 눈에는 잘 안 들어오는데 위력은 붙어 있는 삼과 같아서, 신경망이 놓치기 쉬운 형태 중 하나였어.
9. 쌍삼 / 사삼 / 쌍사 (double three / four-three / double four)
한 수로 위협 두 개를 동시에 만드는 수야. 상대는 하나밖에 못 막으니까 이기게 돼. 이걸 통틀어 "포크(fork)"라고 불러. 자유룰에서는 쌍삼도 허용이야. double_three_test.py는 이걸 확인하던 스크립트야.
10. 포크 (fork)
체스 용어를 빌려온 말로, 한 수가 위협 두 개를 만드는 걸 말해. 프로젝트에서는 alphago_lee.py의 fork mask(포크가 생기는 칸을 표시하는 입력 평면), C++로 빠르게 만든 fork_mask_cpp, 포크 커리큘럼처럼 여러 곳에 등장해. "7-ply 포크 공격 문제"(p7)가 바로 포크를 정확히 읽는지 보는 시험이야.
11. VCF / VCT (Victory by Continuous Fours / Threats)
VCF는 사(四)만 연속으로 두어서 강제로 이기는 수순이고, VCT는 삼까지 섞어서 이기는 수순이야. 상대가 매번 강제로 응수해야 하니까 탐색 나무가 아주 좁아져. 그래서 고전 오목 엔진들이 이걸 전용 탐색으로 풀어. 이 프로젝트의 엔진은 VCF 전용 탐색기가 없고, MCTS-Solver로 확정 승/패를 전파하는 쪽으로 같은 효과를 일부만 얻어.
12. 조용한 위협 (quiet threat)
당장 사나 삼을 만들지는 않지만 몇 수 뒤에 포크로 이어지는 "준비 수"야. 강제 응수를 요구하지 않으니까 탐색이 이걸 "급하지 않다"고 보고 넘겨버리기 쉬워. 이 프로젝트에서 가장 오래 남은 약점이야(6.7 참고). 관찰용 문제 rapfi_cand3_diag_defense와 졸업 문제 webB_quiet_three_defense가 이 약점을 재.
13. 강제승 (forced win)
상대가 어떻게 받아도 이기는 수순이 있는 상태야. "5-ply 강제승 공격"은 다섯 플라이 안에 끝나는 강제승을 찾는 문제야.
14. 선공 필승 (first-player win)
자유룰 15x15 오목은 선공이 이긴다는 게 증명돼 있어(Allis 1994, 6.6 참고). 그래서 15x15로 넘어가면 오프닝 균형 장치(swap2 같은)를 고려해야 해. 11x11 자유룰이 선공 필승인지는 이 프로젝트에서 확인하지 않았어.
15. 스왑2 (swap2)
한 사람이 처음 돌 세 개를 놓으면 다른 사람이 어느 색을 잡을지 고르는 오프닝 규칙이야. 선공이 너무 유리한 문제를 줄여줘. 15x15 체크리스트 7번 항목이야.
16. 대칭 (symmetry, D4)
정사각형 판은 회전 4가지와 뒤집기를 합쳐 8가지 대칭이 있어. 이걸 이용해 데이터를 8배로 늘리거나(데이터 증강) 같은 오프닝을 하나로 묶을 수 있어(_canonical_symmetry_openings).
17. 제로섬 / 완전정보 게임 (zero-sum / perfect information)
한쪽의 이득이 곧 다른 쪽의 손해이고, 숨겨진 정보가 없는 게임이야. 이런 게임에서는 가치 v를 "현재 둘 차례인 사람 입장에서 [-1, 1]"로 정의하고, 한 칸 내려갈 때마다 부호를 뒤집는 negamax 방식이 성립해.
18. 미니맥스 / 네가맥스 (minimax / negamax)
나는 내 점수를 최대화하고 상대는 최소화한다고 가정하고 나무 끝까지 계산하는 고전 알고리즘이야. 네가맥스는 "상대 점수 = -내 점수"를 써서 코드를 하나로 합친 형태야. 3x3 시절의 결정론적 미니맥스 AI, 그리고 11x11의 depth-2 결정론 기준선(determinisic_play.py, 파일명 오타 그대로)이 이 계열이야.

B. 신경망과 학습

19. 신경망 (neural network)
숫자를 받아서 곱하고 더하고 비선형 함수를 거치는 과정을 여러 층 쌓은 함수야. 여기서는 판 상태를 받아서 "어디에 둘지(정책)"와 "누가 이길지(가치)"를 동시에 내놓는 함수로 써.
20. 입력 평면 (input planes)
판을 11x11 크기 숫자판 여러 장으로 바꾼 거야. NUM_INPUT_CHANNELS = 5이니까 5장이고, 내 돌, 상대 돌, 차례 같은 정보와 포크 마스크 등이 들어가. 각 장이 정확히 뭘 담는지는 2부를 봐. 여기서는 "5장"이라는 숫자만 확인했어.
21. 합성곱 (convolution, Conv2d)
3x3 같은 작은 창을 판 위로 밀면서 같은 가중치로 계산하는 층이야. 판 위 어디서나 "삼" 같은 같은 무늬를 같은 방식으로 알아봐. 이게 보드게임에 CNN을 쓰는 이유야.
22. 잔차 블록 (residual block, ResNet)
출력에 입력을 그대로 더해주는(skip connection) 블록이야. 깊게 쌓아도 학습이 잘 돼. 현재 11x11 네트워크는 alphago_lee_v2_seblock.py의 기본값 기준으로 256채널, 잔차 블록 7개야(num_channels = 256, num_res_blocks = 7).
23. SE 블록 (Squeeze-and-Excitation)
판 전체를 평균 내서(squeeze) 채널마다 중요도(0~1)를 계산하고, 그 값을 채널에 곱해주는(excitation) 장치야. 코드는 AdaptiveAvgPool2d(1) → 1x1 conv → ReLU → 1x1 conv → Sigmoid 순서고, reduction=16이야. 판 전체 상황을 국소 계산에 알려주는 "전역 정보 통로" 역할을 해.
24. 그룹 정규화 (GroupNorm)
채널을 몇 묶음으로 나눠서 묶음 안에서 평균 0, 분산 1로 맞춰주는 정규화야. BatchNorm과 달리 배치 크기에 영향을 받지 않아. 자가대국 추론은 배치가 들쭉날쭉해서 이 점이 중요했어. 코드에서는 _group_norm(...)이야.
25. DSConv (depthwise-separable convolution)
합성곱을 채널별 3x3과 1x1 두 단계로 나눠서 계산량을 줄이는 기법이야. 그런데 코드 주석을 보면 이 GPU(GTX 1050)에서는 실제 속도가 "far slower wall-clock"으로 측정돼서 포기했어. 지금 DSConv라는 이름의 클래스는 일반 3x3 conv에 GroupNorm을 붙인 것뿐이야(이름만 남은 셈).
26. 정책 헤드 (policy head)
몸통(trunk) 출력에서 121칸 각각에 둘 확률을 뽑는 출력부야. 지금은 nn.Linear가 121칸에 묶여 있어서 판 크기를 바꾸면 다시 써야 해(15x15 체크리스트 2번).
27. 가치 헤드 (value head)
현재 국면의 기대 결과를 [-1, 1] 사이 값 하나로 내놓는 출력부야. 2026-09-27에 Hard-7 오염 때문에 ep408에서 이 헤드만 다시 초기화한 적이 있어(value_head_reset.py, 메모리 노트 project_value_head_reset).
28. 생존 헤드 (survival head, V3 보조 헤드)
alphago_lee_v3_survival.py에서 추가한 보조 출력이야. "이 판이 앞으로 몇 수 더 갈까"를 예측해. 값은 SURVIVAL_CAP = 40으로 잘라 쓰고, 손실 가중치는 SURVIVAL_LOSS_WEIGHT = 0.25야. 승패 하나보다 촘촘한 학습 신호를 주려는 KataGo식 보조 목표야. 대국에는 쓰지 않고 학습에만 써.
29. 소프트맥스 / 로짓 (softmax / logit)
로짓은 정규화하기 전의 원래 점수고, 소프트맥스는 이걸 합이 1인 확률로 바꿔주는 함수야. 이미 돌이 있는 칸은 로짓을 -∞로 만들어서(마스킹) 확률 0으로 만들어.
30. 손실 함수 (loss)
모델이 얼마나 틀렸는지를 숫자로 나타낸 거야. AlphaZero 손실은 (가치 MSE) + (정책 교차엔트로피) + (가중치 감쇠)이고, 여기에 생존 손실이 더해져.
31. 교차엔트로피 (cross-entropy)
정책 출력 p가 목표 분포 π(MCTS 방문 비율)와 얼마나 다른지 재는 값이야. -Σ π log p로 계산해.
32. MSE (mean squared error)
가치 예측 v와 목표 z 차이의 제곱 평균이야.
33. Adam 옵티마이저
파라미터마다 학습률을 따로 조정해주는 경사하강법이야. 현재 코드는 optim.Adam(model.parameters(), lr=0.00005, weight_decay=1e-4)야.
34. 학습률 (learning rate, LR)
한 번 업데이트할 때 얼마나 크게 움직일지 정하는 값이야. 2026-09-21 "lr-fix"에서 1e-3 대신 1e-4로 바꿨고, 2026-09-30에는 밴드를 5e-5~1e-5로 절반으로 줄였어. 주석에 근거가 남아 있어: 1e-3에서는 가중치가 1.86배 더 멀리 표류(drift)했다.
35. 코사인 재시작 스케줄 (cosine warm restarts, T_0)
학습률을 코사인 곡선 모양으로 줄였다가 주기 T_0마다 다시 올리는 스케줄이야(SGDR). 주석에는 "T_0 450->150"으로 바꿨다고 적혀 있어. 현재 밴드(5e-5 → 1e-5)의 정확한 스케줄 구현은 3부를 참고하고, 여기서는 상한과 하한 값만 확인했어.
36. 가중치 감쇠 (weight decay)
가중치가 너무 커지지 않게 손실에 작은 벌점을 주는 거야. 값은 1e-4야.
37. 배치 (batch)
한 번 업데이트할 때 같이 쓰는 샘플 묶음이야. 학습 배치는 batch_size=128이야. 자가대국 추론 배치는 다른 개념이야(DEFAULT_TARGET_BATCH = 24).
38. 에폭 (epoch)
이 프로젝트에서 에폭은 "데이터셋을 한 바퀴 도는 것"이 아니야. "자가대국 한 묶음 생성 → 학습 → (가끔) 평가" 한 사이클을 뜻해. ep625, ep645 같은 번호가 이 사이클 번호야.
39. 과적합 / 표류 (overfitting / drift)
과적합은 학습 데이터만 외우는 현상이고, 표류는 체크포인트가 좋은 지점에서 점점 멀어지는 현상이야. 9월 하순에는 손실은 계속 내려가는데 게이트는 막혀 있는 일이 반복됐어. 그래서 "손실이 아니라 실력(게이트, 래더, 문제)으로 판단한다"는 원칙이 생겼어.
40. 체크포인트 (checkpoint, .pth)
모델 가중치를 저장한 파일이야. model/best_mcts_11x11.pth는 현재 최강, model_MCTS_epNNN_11x11.pth는 에폭별 스냅샷, graduated_11x11/ep625_graduated_20260929.pth는 졸업 모델(동결)이야.
41. 지도학습 사전학습 (supervised pretrain)
자가대국 대신 이미 있는 기보(결정론 AI 대국 등)로 먼저 정책을 흉내 내게 하는 단계야. Gen7→Gen8, Gen10 재시작에서 썼다고 코드 주석에 적혀 있어.
42. 데이터 증강 (augmentation)
판을 회전하거나 뒤집어서 학습 샘플을 늘리는 거야.

C. MCTS와 탐색

43. MCTS (Monte Carlo Tree Search)
가능한 수를 나무로 펼쳐 놓고, 유망한 가지를 더 많이 방문하면서 통계를 쌓는 탐색이야. 한 번의 "시뮬레이션"은 선택 → 확장 → 평가 → 역전파 네 단계로 이뤄져. AlphaZero에서는 무작위 롤아웃 대신 신경망 가치로 평가해.
44. 시뮬레이션 / 플레이아웃 / sims
뿌리에서 잎까지 한 번 내려갔다 올라오는 것. "1100 sims"는 한 수를 두기 위해 이걸 1100번 했다는 뜻이야. 웹 난이도도 이 숫자로 정해.
45. N, W, Q
각 자식 노드의 방문 횟수 N, 가치 합 W, 평균 Q = W/N이야.
46. 사전확률 P (prior)
정책 헤드가 준 확률이야. 아직 방문하지 않은 수 중에서 어떤 걸 먼저 볼지 정하는 데 써.
47. PUCT
선택 공식 Q + c·P·√N_parent / (1+N)이야. 앞쪽 항(Q)은 활용, 뒤쪽 항은 탐험이야.
48. c_puct
탐험 항의 세기야. 현재 자가대국과 평가 모두 1.6이야(c_puct=1.6, c_puct_exploit=1.6).
49. 디리클레 노이즈 (Dirichlet noise)
뿌리의 사전확률에 무작위 분포를 섞어서 다양한 수를 시도하게 만드는 장치야. 섞는 공식은 (1-ε)P + ε·Dir(α)이야. ε은 noise_weight(0.25에서 0.10으로 감소), α는 dirichlet_alpha(0.3에서 0.15로 감소)야.
50. 노이즈 어닐링 (noise annealing)
노이즈를 학습 초반에는 크게, 나중에는 작게 줄여가는 거야. noise_anneal_epochs=150 동안 선형으로 바뀌는 걸로 보이는데, 정확한 보간 방식은 코드에서 직접 확인하지 않았어.
51. 온도 (temperature)
방문 수 분포에서 수를 뽑을 때 얼마나 무작위로 할지 정하는 값이야. 처음 temperature_moves=4수까지는 방문 비율대로 뽑고, 그 뒤에는 가장 많이 방문한 수를 골라(greedy).
52. 가상 손실 (virtual loss)
여러 시뮬레이션을 동시에 진행할 때, 지금 탐색 중인 경로를 일시적으로 "지는 경로"처럼 보이게 해서 다른 경로로 흩어지게 하는 장치야. 2026-09-25에 부호 버그를 고쳤어(mcts_core.pyd.bak_before_mate_vlfix_20260925). 부호가 뒤집혀 있으면 오히려 같은 경로로 몰려가.
53. 메이트 거리 (mate distance)
같은 승리라도 빨리 이기는 쪽을, 같은 패배라도 늦게 지는 쪽을 더 좋게 보게 하는 보정이야. C++ 코드에서 mag = 1.0 - MATE_DISTANCE_ALPHA * depth(α=0.005)로 계산하고, 하한은 MATE_DISTANCE_FLOOR = 0.5야.
54. MCTS-Solver
잎에서 승패가 확정되면 그걸 "증명된 값"으로 위로 전파하는 기법이야. 자식 중 하나라도 확정 승이면 부모는 확정 승이고, 모든 자식이 확정 패면 부모는 확정 패야. 통계적 추정보다 강해서 수읽기 문제에 결정적이야. 2026-09-27에 도입했어(mcts_core_solver.cpp).
55. 강제 플레이아웃 (forced playouts)
KataGo 기법이야. 뿌리 자식마다 최소 √(k·P·N) 정도는 방문하게 강제해서, 사전확률이 낮은 좋은 수가 묻히지 않게 해. FORCED_PLAYOUT_K = 2.0이고 2026-09-28에 도입했어.
56. 정책 목표 가지치기 (policy target pruning)
강제로 준 방문은 학습 목표 π에서 다시 빼주는 짝 기법이야. 안 빼면 노이즈가 목표에 섞여. 이 프로젝트 구현에 이 부분이 정확히 어떻게 들어갔는지는 3부/4부를 봐. 여기서는 확인하지 않았어.
57. 트리 재사용 (tree reuse)
수를 둔 뒤 그 수 아래의 부분 나무를 버리지 않고 다음 탐색의 뿌리로 쓰는 거야. 계산을 아낄 수 있어(mcts_core_tree_reuse.pyd).
58. PV (principal variation)
방문 수가 가장 많은 자식을 따라 내려간 "예상 수순"이야. 웹 분석판에서 AI가 어떤 수순을 예상하는지 보여주는 데 써.
59. 후보 반경 (neighbor radius)
모든 빈칸이 아니라 기존 돌에서 거리 2 안에 있는 칸만 후보로 보는 가지치기야(NEIGHBOR_RADIUS = 2). 후보가 약 45개로 줄어들어. 2026-09-10 분석에서는 250 sims로는 후보당 방문이 약 5번밖에 안 돼서 2-ply 반박도 못 본다는 진단이 나왔어.
60. 부스트 sims (boosted sims)
국면이 "좁을 때"(후보가 적거나 위급할 때) 탐색 수를 늘리는 장치야. boosted_sims=1800, boost_threshold=5, boost_when_narrow=True.
61. PCR (Playout Cap Randomization)
KataGo 기법이야. 수마다 확률 p로 "풀 탐색"(900 sims)을 하고, 나머지는 "빠른 탐색"(150 sims)을 해. 학습 목표로는 풀 탐색한 수만 기록해. 게임 수는 늘리면서 목표 품질은 지킬 수 있어. full_search_prob=0.5, fast_sims=150.
62. 루트 병렬 / 배치 추론 (batched inference)
여러 게임과 여러 시뮬레이션의 잎 평가를 모아서 GPU에 한 번에 보내는 거야. 통합 풀은 목표 배치 24, 최대 대기 0.015초로 묶어(DEFAULT_TARGET_BATCH, DEFAULT_MAX_WAIT).
63. 탐욕 선택 (greedy)
노이즈와 온도 없이 방문 수 최대인 수를 고르는 거야. 공정한 평가는 항상 이 방식으로 해(메모리: league eval framing).

D. AlphaZero 학습 루프

64. 자가대국 (self-play)
현재 모델끼리 두게 해서 학습 데이터를 만드는 거야. 에폭당 num_self_play_games=16판이야.
65. 학습 샘플 (s, π, z)
국면 s, 그 국면에서 MCTS 방문 비율 π, 그리고 최종 결과 z(그 국면의 차례인 쪽 기준 +1/0/-1)의 묶음이야. V3에서는 생존 목표가 다섯 번째 원소로 붙어(NaN이면 없음).
66. z/q 혼합 가치 목표 (mixed value target)
가치 목표를 z(실제 결과)만 쓰지 않고 (1-w)·z + w·q로 섞는 거야. q는 그 국면에서 MCTS가 추정한 값이야. value_target_q_weight=0.5(2026-09-27)이야. 결과 하나가 판 전체 샘플에 똑같이 붙는 잡음을 줄여줘.
67. 가치 라벨 마스킹 (value-label masking)
신뢰할 수 없는 가치 라벨(예: 길이 제한으로 끊긴 판이나 오염된 출처)을 학습에서 빼는 처리야. 15x15 체크리스트 3번에 들어가 있어. 마스킹 조건의 세부는 확인하지 못했어.
68. 리플레이 버퍼 (replay buffer)
최근 샘플을 모아두는 창고야. 최대 REPLAY_BUFFER_MAX_SIZE = 24_000개이고 model/mcts_replay_buffer_11x11.pkl에 저장해.
69. 우선순위 리플레이 (prioritized replay)
오차가 큰 샘플을 더 자주 학습하는 기법이야. 구현은 있지만 현재 꺼져 있어(use_prioritized_replay=False).
70. 게이트 (gate / gating)
새로 학습한 모델이 현재 최강(best) 모델과 대국해서 55% 이상 이겨야(무승부는 0.5) best로 승격하는 관문이야(GATE_PROMOTION_THRESHOLD = 0.55, AlphaGo Zero 값). ep625의 게이트 결과는 20판 W8 D8 L4 = 60%였어.
71. 승격 / 유지 (promoted / kept)
게이트를 통과하면 승격, 못 하면 기존 best를 유지해. "650~700 all kept"는 그 구간에서 계속 유지만 됐다는 뜻이야.
72. 리그 (league)
과거 체크포인트들과 대국해서 "옛날 약점을 다시 잊는" 현상을 막는 장치야. 에폭당 6판, 풀 크기 40, best 체크포인트를 뽑을 확률 0.28이야.
73. 리그 앵커 회전 (league anchor rotation)
2026-09-30에 도입했어. epoch % 3에 따라 리그 상대를 Dawn, ep645, 일반 추첨으로 돌려가며 정해(LEAGUE_ANCHOR_ROTATION = True). 같은 날 시도했던 무작위 앵커 확률(LEAGUE_ANCHOR_PROB)은 0.0으로 꺼졌어.
74. 결정론 상대 (vs-Deterministic, vs-Det)
규칙 기반 C++ AI(deterministic_play_core*.pyd)와의 대국이야. 현재 학습에서는 0판(num_vs_deterministic_games=0, refresh_vsdet_games=0)이야. 초기에는 기준선이자 데이터 출처였어.
75. 커리큘럼 대국 (curriculum games)
특정 전술 형태(닫힌 삼이나 포크 같은)가 나오도록 시작 국면을 만들어준 대국이야. 에폭당 4판이야.
76. 오프닝 대국 (opening games)
대칭을 고려한 정규 오프닝 칸(_OPENING_SQUARES)에서 시작하는 대국이야. 에폭당 2판이야.
77. 게임 길이 제한 (max game plies)
자가대국과 리그 대국을 90플라이에서 끊어(max_game_plies=90, 2026-09-28). 끝없이 늘어지는 판이 자원을 잡아먹는 걸 막아줘. 15x15에서는 이 값을 다시 계산해야 해.
78. 전술 채굴 / 재라벨 (tactical mining / relabel)
대국에서 전술적으로 어려운 국면을 찾아내서, 1800 sims(RELABEL_SIMS)로 다시 탐색해 더 좋은 정책 목표를 붙이는 과정이야. 한 번에 최대 256개(RELABEL_CAP), 하드 예제 풀은 최대 8000개(HARD_EXAMPLE_CAP)야.
79. 하드 예제 풀 (hard example pool)
위에서 재라벨한 샘플을 모아두는 곳이야(model/hard_mined_examples_11x11.pkl).
80. 평평한 엔트로피 판정 (flat entropy)
MCTS 분포가 후보 수의 균등분포(ln n)에 거의 가까우면(FLAT_ENTROPY_MARGIN = 0.05) "아무 정보도 없는 목표"로 보고 걸러내는 판정이야.
81. 전술 리프레시 (tactical refresh)
N 에폭마다 채굴과 재라벨 학습을 끼워 넣는 주기야. 현재 tactical_refresh_interval=5, tactical_refresh_epochs=8이야. 주석에 따르면 게이트 검사도 이 주기를 같이 탄다고 해. NAPS라는 이름은 "tactical_refresh 제거" 계열에서 나왔지만 현재 설정에는 interval=5로 남아 있어. 두 사실이 어떻게 맞물리는지는 3부를 확인해야 해(확인 못 함).
82. Sim 램프 (sim ramp)
정체되면 sims를 150에서 100씩, 최대 1100까지 올리는 자동 장치야(SIM_RAMP_*). 부스트 쪽은 300에서 200씩, 최대 2200까지야. STAGNATION_RAMP_LIMIT = 5, LR_COOLDOWN_EPOCHS = 25도 같은 영역의 상수야. 현재 실행에서 램프가 실제로 동작 중인지는 확인하지 않았어.
83. 가중치 (sample weight)
출처별로 샘플 손실에 곱하는 값이야. 이긴 쪽 자가대국 수 1.15, vs-Det 1.5, 리그 1.25야(selfplay_mp_unified.py).

hlt/web/server.py와 index.html이야. 사람과 대국하면서 후보수 상위 12개(TOP_K = 12), 승률, PV를 보여줘. 모델 선택(최신/여명), 무르기, SGF 저장 기능이 있어.
94. 난이도 (difficulty levels)
sims 수로 나눠. 150 미만은 입문, 400 미만은 쉬움, 800 미만은 보통, 1500 미만은 어려움, 그 이상은 최강이야(LEVEL_NAMES). 공개 링크의 상한은 MAX_SIMS = 2000이고, 입력 범위는 50~2000이야.
95. HLT GUI
웹판 이전의 데스크톱 대국 GUI야(hlt/hlt_gui_v3.py). HLT가 무엇의 약자인지는 확인하지 못했어.

F. 평가와 측정

96. Rapfi
Gomocup 상위권의 공개 오목 엔진이야. 이 프로젝트의 외부 잣대고, 노드 수(한 수당 탐색량)를 제한해서 강도를 조절해.
97. Rapfi 래더 (ladder)
노드 300/1000/2000/3000 네 단계의 Rapfi와 각각 20판씩, 고정된 20개 오프닝으로 노이즈 없이 두는 측정이야. 결정론적이라서 같은 모델은 같은 결과가 나와. rapfi_ladder_watch.py가 20에폭마다 자동으로 돌려.
98. 동등 노드 (equal-strength nodes)
"우리 모델이 50% 승률을 내는 Rapfi 노드 수"야. 2026-09-29부터는 모든 단계의 결과를 써서, 판 수로 가중한 최소제곱법으로 Elo를 log10(nodes)에 대해 직선 적합한 뒤 50% 지점을 구해. 예전 방식(한 번 교차하는 지점)은 equal_nodes_crossing으로 남아 있어. 예전 방식은 잡음에 약했어(ep555: 예전 1246 → 적합 575).
99. Elo
승률 차이를 점수 차이로 바꾸는 척도야. 기대승률 = 1/(1+10^(-Δ/400)). 50% = Δ0, 64% ≈ +100이야.
100. 공정 재측정 (fair greedy re-measurement)
학습 중에 노이즈를 낀 채 잰 리그 승률 말고, 노이즈 없는 greedy 대국으로 다시 잰 승률이 진짜라는 원칙이야(eval_league_greedy.py).
101. 시간 맞춘 대국 (time-matched match)
sims를 고정하지 않고 상대와 같은 벽시계 시간을 쓰게 한 대국이야. gomokuwithai Hard 상대로 Dawn(약 2k sims)이 20판 6승 9무 5패 = 52%였어(1100 sims 고정 50판에서는 29%).
102. gomokuwithai
외부 웹 오목 AI야. gomokuwithai_match.py로 대국하고, 로그는 model/gomokuwithai_match*_log.jsonl에 남아.
103. 손실 추세 그래프 (loss trend)
loss_trend_annotated.py가 그리는 손실 곡선이고 이벤트 주석이 달려 있어. 시간마다 도는 hourly_status.py 점검과 함께 써.
104. 신뢰구간 / 표본 크기
20판에서 55%는 표준오차가 약 ±11%p야(√(0.25/20) ≈ 0.11). 그래서 래더 한 번, 게이트 한 번 결과는 크게 흔들려. 적합 방식으로 바꾼 것도 이 문제 때문이야.

G. 시스템과 엔지니어링

105. pybind11 / .pyd
C++ 코드를 파이썬 모듈로 감싸주는 라이브러리야. 윈도우에서 빌드된 확장 모듈은 .pyd 파일이 돼(mcts_core_solver.pyd 등). 빌드는 build_mcts_core_solver.bat로 해.
106. 멀티프로세싱 spawn / main 가드
윈도우는 자식 프로세스가 메인 파일을 다시 import해. 그래서 if __name__ == "__main__": 가드가 없으면 자식마다 학습을 처음부터 다시 시작해버려. 실제로 평가 프로세스가 60초 안에 준비 신호를 못 보낸 사고가 있었어.
107. 단일 인스턴스 락 (train.lock)
학습기가 두 개 뜨는 걸 막는 PID 파일이야. 2026-09-23에 예약 작업의 LogonTrigger가 두 번째 학습기를 띄워서 18시간 동안 같은 파일에 같이 쓴 사고 뒤에 만들었어.
108. 워치독 (watchdog)
학습기가 죽으면 다시 살리는 감시 스크립트야(watchdog_.py, restart_trainer.ps1).
109. 킬 스위치 파일
특정 파일이 존재하면 기능을 끄는 방식이야(MP_UNIFIED_OFF, 예전 MP_SELFPLAY_OFF). 재시작 없이 끌 수 있어.
110. .bak 백업 관례
수정하기 전에 파일명.bak_before_무엇_날짜로 복사해두는 관례야. 파일 이름만 봐도 변경 역사를 거의 다 복원할 수 있어(6.5 참고).
111. 핫 리로드 (hot reload)
웹 서버가 재시작 없이 새 best 체크포인트를 불러오는 기능이야(server.py.bak_before_hotreload로 도입 시점을 알 수 있어).
112. 스톨 타임아웃 (stall timeout)
통합 풀에서 180초(DEFAULT_STALL_TIMEOUT) 동안 진행이 없으면 실패로 처리하는 시간이야.

6.7 남은 문제

1. 방어 맹점: 멀리 있는 조용한 위협

공격 문제(p5, p7)는 3/3으로 안정적인데, 방어 쪽은 아직 흔들려. 졸업 시점 기록은 webB 조용한 삼 방어 2/3, 관찰용 코너 대각 방어 0/3이었어. 원인 가설은 이래. 첫째, PUCT는 사전확률 P가 낮은 수를 거의 보지 않아. 둘째, 조용한 수는 강제 응수가 아니라서 MCTS-Solver의 확정값이 생기지 않아. 셋째, 반경 2 후보 생성은 "싸움터에서 먼" 칸을 아예 후보에서 빼버릴 수 있어. ep730이 코너 대각 문제를 처음으로 풀었다는 기록(메모리, 2026-09-30)이 있지만, 이게 일반화된 건지 한 번 운이 좋았던 건지는 아직 몰라.

2. 가치 과낙관 (value over-optimism)

가치 헤드가 실제보다 자기 쪽에 유리하게 판단하는 경향이야. Hard-7 오염(ep408 재초기화)이 대표 사례고, z/q 혼합과 라벨 마스킹이 그 대응책이야. 낙관이 남아 있으면 PUCT가 위험한 가지를 "괜찮다"고 보고 덜 파게 돼. 그러면 방어 맹점이 더 커져. 지금 얼마나 낙관적인지를 정량적으로 잰 최신 수치는 이 부록에서 확인하지 않았어.

3. 13-ply 방어

사용자가 너무 어렵다고 보고 2단계 기준으로 옮긴 문제인데, ep625가 3/3으로 통과했어. 다만 sims를 900/1100/1300으로 정해두고 푼 결과라서, 웹 "쉬움"이나 "보통"(400~800 sims)에서도 막는다는 보장은 없어. 실제로 사람과 둘 때의 강도는 sims에 따라 달라져.

4. 측정의 잡음

래더는 레벨당 20판이라 표준오차가 약 ±11%p야. 게이트도 20판이야. 동등 노드 수치(예: ep545 약 120, ep555 약 575)가 크게 흔들린 것도 이 때문이야. 결정론적으로 같은 오프닝만 쓰니까, 같은 모델은 같은 결과가 나오지만 "오프닝 표본 편향"은 남아 있어.

5. 게이트 정체

650~720 구간에서 15번 연속 유지만 됐어. 그래서 LR을 절반으로 줄이고 앵커 회전을 도입했고, ep730이 승격됐어. 이 효과가 계속 이어질지는 시험 뒤에 판단할 거야.

6.8 시험 끝나고 할 일

  1. 각성 모드. 사용자가 이름 붙인 아이디어야. 대화 기록을 "각성 모드"와 "awakening"으로 검색해봤는데, 정의를 담은 구절은 찾지 못했어(대화 기록에는 "각성(Awakening) = 원인을 처음 깨달은 순간"이라는 다른 맥락만 나와). 그래서 내용은 확인 못 함이야. 시험이 끝나면 사용자에게 정의를 다시 받아서 설계해야 해.
  2. "아주 쉬움" 난이도. 입문 설정(150 sims 미만)에서도 사람이 선공으로 졌다는 관찰이 있었어. 그래서 50회 정도의 "아주 쉬움"을 제안했지만 아직 구현하지 않았어. 할 일: LEVEL_NAMES에 (예: 100, "아주 쉬움")을 앞에 추가하고, index.html의 LEVELS 배열과 설명문을 맞춰서 고치고, 입력 min이 50인지 확인하기. 축제 관람객이 "이길 수 있는" 경험을 하려면 sims만 줄이는 것보다 온도를 넣어서 일부러 실수하게 하는 게 더 사람다울 수도 있어(검토 대상).
  3. 학습 끈 상태로 부하 테스트. 지금 동시 접속 추정치는 학습과 GPU를 나눠 쓰는 상태에서 나온 거야. 축제 날에는 학습을 끄니까, 그 조건으로 가상 접속자 여러 명을 만들어 응답 시간을 재야 해. 서버에는 배칭 기능이 들어가 있어(server.py.bak_before_batching_20260928).
  4. 11x11 종료 판단. 장학금 기준(동등 노드 2000)에 도달했는지, 아니면 정지 규칙을 적용할지 결정하기.
  5. 15x15 착수(다음 절).
